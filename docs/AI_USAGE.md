# 🤖 AIクライアントから使う（Claude Code / Claude Desktop） / Use from an AI client

この拡張機能には[Model Context Protocol (MCP)](https://modelcontextprotocol.io/)サーバーが内蔵されており、Claude Code・Claude Desktopなどの外部AIクライアントから、VBAコードの読み取り・検索・マクロ実行に加えて、**AIが書いたコードをExcelのVBAモジュールへ直接書き込む**ことができます（`excel_update_module_code`ツール）。

このMCPサーバー（`dist-server/server.js`）はNode単体で動作するため、**VS Codeを開いていなくても**AIクライアントから直接起動・利用できます（ただしExcel本体とVBA実行環境はWindows上に必要です）。

## 1. セットアップ

### 1.1 外部AIクライアント（Claude Code / Claude Desktop）

1. VS Codeでこの拡張機能をインストールした状態で、コマンドパレット（`Ctrl+Shift+P`）から **`Excel VBA: Print MCP Server Config (for AI)`** を実行する
2. 生成されたJSON（クリップボードにコピー済み）を設定ファイル（Claude Codeなら`.mcp.json`、Claude Desktopなら`claude_desktop_config.json`）へ反映する
   - 設定ファイルがまだ存在しない場合：生成されたJSONをそのままファイルの内容として保存する
   - 設定ファイルが既に存在する場合：ファイル全体を上書きせず、既存の`mcpServers`オブジェクトの中に`excel-vba-sync`のエントリだけを追記する（他のMCPサーバーの設定を消さないよう注意）
3. AIクライアントを再起動すると、`ping` / `excel_list_modules` / `excel_get_module_code` / `excel_list_macros` / `excel_run_macro` / `vba_search_code` / `excel_update_module_code`の7ツールが使えるようになる

### 1.2 VS Code内蔵・VS Code拡張機能型のAIクライアント（Copilot Chat / Codex 等）

上記のセットアップ手順は外部AIクライアント（Claude Code/Desktopなど、独立した設定ファイルにMCPサーバー情報を記述するタイプ）向けです。VS Code標準のMCP連携機能（`contributes.mcpServerDefinitionProviders`）を使って実装されているAIクライアントには、この拡張機能自身がMCPサーバーを自動的に登録します。**手動設定は不要**で、拡張機能をインストールするだけで検出されます（起動される内容は上記の手動設定と同一）。`onStartupFinished`のような明示的な起動イベントを追加しなくても自動的に有効化されることを確認済みです。

実機で自動検出を確認済みのクライアント：
- **Copilot Chat**（エージェントモード） — ツール選択画面に表示され、動作確認済み
- **Codex**（VS Code拡張機能版） — ツール選択の手動登録（「カスタムMCPに接続する」フォーム）は不要で、何も設定せずにモジュール一覧・マクロ一覧・ソースコード取得が正しく動作することを確認済み

これらのクライアントのツール選択画面には`vba-excel-mcp`という名前（サーバー自身がMCPプロトコルで名乗る識別子）で表示されます。あわせて人間向けの表示名（`title: "Excel VBA Sync"`）と、サーバーの使い方を要約した`instructions`（`workbookPath`を優先すること、`dryRun`/`confirmToken`の書き込みフロー等）も設定していますが、これらをクライアントのUIがどう表示するかはクライアント次第です。

自動検出されない場合は、Codexの設定画面にある「カスタムMCPに接続する」のようなクライアント独自の手動登録フォームを試してください（上記「Excel VBA: Print MCP Server Config (for AI)」で生成される`command`/`args`/`env`の値をそのまま使えます）。

### 1.3 複数クライアントを同時に使う場合の注意

Claude Code/Desktop（手動設定）とVS Code内蔵・VS Code拡張機能型のAIクライアント（自動検出）を同時に使う場合、それぞれが独立した`server.js`プロセスを起動します（MCPの標準的な設計であり不具合ではありません）。同時に複数のクライアントがExcel操作を行うと、後述の「複数Excelプロセスに関する注意」のリスクが顕在化しやすくなる点にご留意ください。

## 2. ツールの使い方のコツ

**「モジュール一覧が欲しいだけ」なら`excel_list_modules`を使う**
モジュール名・種別・行数だけが欲しい場合、`vba_search_code`に`.*`のような全行マッチの正規表現を投げるのは避けてください。コード内容を全く読まずに軽量・高速に一覧を返す`excel_list_modules`が専用に用意されています（実際にCopilot Chatのエージェントがこの目的で`vba_search_code`を力技で使い、巨大な結果でエラーになった実例があったため追加されました）。

**「ワークブック全体のマクロ一覧が欲しい」なら`moduleName`を省略する**
`excel_list_macros`の`moduleName`は省略可能です。省略すると対象ワークブックの全モジュールのマクロを1回の呼び出しでまとめて返します。「モジュールごとに1回ずつ`excel_list_macros`を呼ぶ」というループは避けてください。Excel/ワークブックの解決処理がモジュール数だけ繰り返されるため、実際にCopilot Chatのセッションで応答が返ってこない（タイムアウトのように見える）事例がありました。

## 3. 書き込み（`excel_update_module_code`）の安全設計

- `dryRun:true`でまず呼び出すと、実際には書き込まず、現在のコードとの差分プレビュー＋`confirmToken`が返る
- 同じ`confirmToken`を付けて再度呼び出すことで、初めて実際にExcelへ書き込まれる（AIが誤って一発で書き込んでしまうことを防ぐ2段階フロー）
- `confirmToken`はdry-run時点のモジュールのコードに紐付いており、書き込み直前にモジュールを再読込してトークンを再計算・照合する（楽観的排他制御）。dry-runから確定までの間に**別のクライアント（別のAI/別セッション等）が同じモジュールを先に書き換えていた場合**、トークンが一致せず`ERR_MODULE_CHANGED_SINCE_DRYRUN`で書き込みが拒否される（気づかずに上書きすることを防ぐ。実機で2クライアントの競合を再現し、後勝ちの上書きが正しく拒否されることを確認済み）
- 書き込み前には自動的に現在のコードがワークブックと同じフォルダの`.excel-vba-sync-backups`にタイムスタンプ付きで退避される
- Sheet/ThisWorkbookのコードビハインド（Documentモジュール）に書き込んだ場合、ショートカットキー割り当てなどのプロシージャ単位のAttribute情報はVBAのAPI制約上失われる（レスポンスに警告が入る）

## 4. Excelプロセスの自動解決

### 4.1 workbookPathによる自動起動・自動オープン

`excel_get_module_code` / `excel_list_macros` / `excel_run_macro` / `vba_search_code` / `excel_update_module_code`はいずれも`workbookPath`（ワークブックのフルパス）を指定できます。指定した場合、Excelが起動していなければ自動的に起動し、対象ブックが未オープンであれば自動的に開いてから操作します。Excelのトラストセンターで「VBAプロジェクトオブジェクトモデルへのアクセスを信頼する」が有効になっている必要があり、無効な場合は`ERR_VBOM_TRUST_DISABLED`という分かりやすいエラーが返ります（この設定はプログラムから自動的に有効化することはできません）。

対象ワークブックの状態によって、内部的な挙動と結果に以下の違いがあります。

| 状態 | Excel起動 | ワークブックOpen | `launchedExcelPid` | 速度 |
|---|---|---|---|---|
| ① 対象ファイルが既に開かれている | 既存を再利用 | 既に開いている（何もしない） | 付かない | 最速 |
| ② Excelは起動中だが対象ファイルは未オープン | 既存を再利用 | 自動でOpen | 付かない | 中速 |
| ③ Excel自体が未起動 | 新規起動（`Visible=$true`のまま） | 起動後に自動でOpen | **付く**（新規プロセスIDを報告） | 最も遅い |

- **`launchedExcelPid`の有無**は「このツール呼び出しでExcelプロセス自体を新規に起動したか」を示す唯一の手がかりです。③のときだけ付きます。①②は既存のExcelプロセスを再利用するだけなので付きません。
- **①（既に開いている）の場合、ユーザーの作業状態がそのまま影響を受けます。** ユーザーが手作業でそのブックを編集・選択中であっても、AI側の操作は同じ生きているセッションに対して行われます。ユーザーが何か操作中（ダイアログ表示中等）だと、COM呼び出しが一時的に競合する可能性があります。
- **`workbook`（表示名のみ、`workbookPath`なし）で呼んだ場合、①（既に開いている）でしか解決できません。** ②③のようにまだ開かれていない状態からは、ファイルパスが分からず自動で開けないため失敗します。確実性を優先するなら、対象が既に開いているかどうかによらず**常に`workbookPath`を渡す**ことを推奨します。
- 後始末の方針は変わりません：③で新規起動したExcelも、処理後は開いたままです（上記の意図的な設計）。

### 4.2 複数Excelプロセスに関する注意

`workbookPath`指定でExcelが未起動の場合に自動起動されたインスタンスは、処理後も**開いたままになります**（意図的な設計）。この状態でユーザーが別途Excelを手動で起動する（または既に起動していた）と、Excelプロセスが2つ並存し、`GetActiveObject`がどちらを掴むか不定になり、VS Code UIのExport/Importコマンドなどが「保存済みのブックが見つからない」といった不可解なエラーを起こすことがあります。これを見分けやすくするため、ツール呼び出し中に**新規でExcelを自動起動した場合のみ**、レスポンスの`launchedExcelPid`にそのプロセスIDが入ります（既存のExcelを再利用した場合は含まれません）。心当たりのないエラーが出た場合は、タスクマネージャーで`EXCEL.EXE`が複数起動していないか確認してください。

## 5. マクロ実行（`excel_run_macro`）に関する注意

- `timeoutMs`（既定30秒）を超えると呼び出しは`ERR_TIMEOUT`で打ち切られるが、これは**こちら側の待ちを止めるだけ**で、`MsgBox`・`InputBox`・フォーム表示等でExcel自体がダイアログ待ちで固まっている状態は解消されない。タイムアウトが出た場合はExcel画面を直接確認すること
- ツールが`isError`を返さなかった（＝例外を投げずに完走した）からといって、マクロが**意図した通りに**動作したことは保証されない。セル操作・ファイル出力・イミディエイトウィンドウ出力などの結果は、このMCPサーバーからは直接検証できないため、実行後に何を確認すべきかは呼び出し側が判断する必要がある
- VBAは**プロジェクト全体を一括コンパイル**する仕様のため、ワークブック内のどこか1モジュールにでもコンパイルエラー（`Option Explicit`下での未宣言変数など）があると、**それとは無関係なマクロを呼んでも全て失敗・ハングする**。呼び出しが原因不明にハングしたりエラーになったりした場合は、まずExcel側にコンパイルエラーのダイアログが出ていないか確認すること

## 6. AIエージェント向けの「リファレンス」について

このMCPサーバーの各ツール・各パラメータには説明文（description）を実装済みで、MCPプロトコル経由でAIクライアントに自動的に渡ります。これが実質的なリファレンスとして機能するため、別途リファレンス文書は用意していません（コードと説明文が常に同期している方が、別ファイルを保守してズレるリスクより信頼できるため）。
